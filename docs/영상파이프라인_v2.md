## [1] 리소스 전달 규격

| 항목 | 권장 |
|---|---|
| 이미지 | 3~5장 (1080px 이상, 제품이 크게 보이는 컷) |
| 영상 | 있으면 WAN 생성 대신 컷 편집으로 활용 (품질 더 좋음) |
| 제품 정보 | 이름 1줄 + 강조 포인트 1~3개 |
| 전달 방법 | 텔레그램 첨부 또는 폴더 지정 (받으면 `data/client_assets/{제품명}/` 보관) |

## [2] WAN 제작 — 학습 코퍼스 패턴 매칭

제품 카테고리별로 코퍼스에서 추출한 성공 패턴 자동 주입:

| 카테고리 | WAN 프롬프트 전략 (v4 검증) |
|---|---|
| 게임 | 캐릭터 피규어화 + 손 + 클로즈업 (전투/파티클 금지 — 1.3B 뭉갬) |
| 제품(신발/옷) | 매크로 회전 + 원단 텍스처 + 순백 스튜디오 (전신샷 금지) |
| 플랫폼/사이트 | UI 클린업 + contain (왜곡 금지) |
| 실패 패턴 | 단색 프레임(variance<30) 자동 감지 → 재생성 |

## [3] Git 리서치 결과 — 적용할 편집/사운드 기법 (08-25 조사)

3. **YumCut** (⭐857) — TS 기반 수직영상 생성기

### 우리 시스템에 적용할 기법 (video-autopilot-kit에서 추출)

**A. 사운드 (3종)**
1. **비트 감지 컷 편집** — BGM의 온셋을 librosa로 감지 → 컷 전환을 비트에 맞춤 (현재: 고정 0.3s fade → 개선)
2. **에너지 기반 더킹 강화** — 나레이션 구간 BGM -18dB, 무음 구간 -10dB로 자동 복귀 (현재: 고정 0.07 볼륨)
3. **리버브 테일** — 클립 전환 시 200ms 오디오 크로스페이드 (끊김 제거)

**B. 편집 (4종)**
4. **pattern interrupt 규칙** — "고정 N초마다 카드" 금지, 문장 에너지 전환 시점에 컷 (그들의 철학 채택)
5. **역할 기반 프레임** — hook/stat/compare/steps/end_card 역할별 레이아웃 (한 프레임 = 한 메시지)
6. **safe zone 준수** — 세로화면 상하 UI 영역 피해서 자막/제품 배치
7. **직접 재구성 원칙** — 가로 소스를 center-crop 하지 않고 세로 전용 재구성 (우리 블러배경+contain 방식과 일치, 유지)

### 우선 적용 순서
- 1차: 비트싱크 컷 (librosa — 이미 설치됨) + 에너지 더킹 → 다음 영상부터
- 2차: pattern interrupt (대본 생성기와 연동 필요)
- 3차: 역할 기반 프레임 템플릿
