# 바이럴 스톰 v3 — 멀티엔진 아키텍처 (2026-08-25)

> 준석(제프) 아키텍처 조언 + MoneyPrinterTurbo(⭐116k) 파이프라인 학습 반영

## 핵심 변경: 단일 엔진 → 4 엔진 분리

**기존 문제 (준석 지적):** 한 엔진이 서칭→라이팅→영상생성→검토를 전부 순차 처리 → WAN GPU 대기 시간에 다른 작업도 전부 멈춤 (GPU 36분×2 = 전체 1시간+)

**새 구조 — 목적별 독립 엔진, 각자 큐/워커:**

```
┌─────────────────────────────────────────────────────────────┐
│                     orchestrator.py (감독)                   │
│   작업 큐(SQLite jobs 테이블) + 상태머신 + 재시도/보고        │
└──────┬──────────────┬──────────────┬──────────────┬─────────┘
       ▼              ▼              ▼              ▼
┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│ E1 브레인    │ │ E2 스튜디오  │ │ E3 검수관    │ │ E4 배포관    │
│ 서칭+라이팅  │ │ 영상 서칭    │ │ QC 게이트    │ │ 플랫폼 업로드│
│             │ │ +제작        │ │             │ │             │
│ ·코퍼스검색  │ │ ·리소스매칭  │ │ ·프레임검수  │ │ ·YT/블로그  │
│ ·대본/카피  │ │ ·WAN큐(독점) │ │  (비전API)  │ │ ·DC/X       │
│ ·플랫폼별글  │ │ ·TTS/BGM    │ │ ·오디오검증  │ │ ·성과수집    │
│ ·이미지키워드│ │ ·편집(비트싱크)│ ·자막확인   │ │ ·리포트      │
└─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘
   CPU만 사용      GPU+CPU         CPU만           네트워크만
   (빠름~수분)     (수분~30분)     (초~분)          (분)
```

**병렬화 효과:**
- E1은 여러 제품의 대본을 미리 찍어냄 → E2가 GPU 쓰는 동안에도 다음 작업 준비 완료
- E2 렌더중에도 E1/E3/E4는 계속 일함 (기존엔 전체 정지)
- E2 내부에서도 TTS/BGM은 WAN과 병렬 가능 (MoneyPrinterTurbo의 독립 스텝 방식)

## MoneyPrinterTurbo에서 채택한 것

| 기법 | 우리 적용 |
|---|---|
| **stop_at 중간산물 파라미터** | job에 stop_at='script'/'audio'/'video' 지정 — 대본만/음성만 따로 뽑아 검증 후 다음 단계 (실패 조기 차단, 크레딧 절약) |
| **컨트롤러/서비스/모델 분리** | engine(API계층) / services(작업계층) / models(스키마) 분리 |
| **태스크 상태머신 (task_id 추적)** | jobs 테이블: pending→searching→writing→rendering→review→queued→posted, 실패 시 단계 기록 |
| **다중 TTS 밴드** | edge-tts 기본 + 감정변주 → 향후 ElevenLabs/Fish Audio 플러그인 슬롯 |
| **Pexels/Pixabay 소스 계층** | 형 리소스(client_assets) > WAN 생성 > (보조)무료소스 — 우선순위 명시 |
| **프리셋 내보내기** | 제품별 생성 프리셋 JSON (폰트/톤/비트/컷수) — 재사용 |

## 엔진별 상세

### E1 브레인 (search + write)
입력: 제품명+리소스메타 / 출력: 대본(감정태그 포함), 플랫폼별 글, 이미지 키워드, 프리셋
- 코퍼스 26,222건에서 카테고리별 상위 패턴 검색 → 대본 구조 결정
- 문장마다 감정태그(hook/body/pop/cta) 부여 → E2가 TTS 톤 자동 적용

### E2 스튜디오 (video search + make)
입력: 대본+리소스 / 출력: 완성 mp4
- 리소스 우선순위: 형 전달분 > WAN(검증프롬프트) > 무료소스
- 비트싱크/에너지더킹/줌펀치 (pro_audio.py)
- 폰트 팔레트: 훅=**BlackHanSans**(임팩트) / 본론=NotoSansKR / CTA=**Jua**(친근)
- WAN 실패(단색프레임) 자동 재생성

### E3 검수관 (review gate)
- 프레임 3개 추출 → 비전 API: 이물질(타 제품/게임화면) 확인, 자막 잘림, 품질 판정
- 오디오: 데시벨/길이/무음구간 체크
- 불통과 → E2에 재생성 요청 (최대 2회) → 재실패 시 보고

### E4 배포관
- 업로드 전 **형 승인 대기열** (기존 규칙 유지: 형에게 먼저)
- 승인 시 플랫폼별 발행 + 성과 수집

## 작업 흐름 예 (나이키 에어포스)

```
형: [이미지5장+제품명] 
 → E1: 대본 5문장 감정태그 (10초) ──────────────┐
 → E2: WAN큐 + TTS병렬 + 비트싱크 렌더 (3~8분) ←─┘
 → E3: 프레임3+오디오 검수 (30초) — 트릭컬 같은 이물질 여기서 차단!
 → 형 승인 → E4 발행
```
※ 트릭컬 이미지 사고(v5)는 E3 게이트에서 자동으로 걸렸을 케이스
